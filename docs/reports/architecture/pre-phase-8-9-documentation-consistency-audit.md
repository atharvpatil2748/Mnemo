## Implementation and operational claims checked

- `config/production/runtime-selection.json` is `UNINDEXED`. `mnemo_server/services/production_runtime_selection.py:49` rejects it; `mnemo_server/app.py` and `mnemo_server/mcp/server.py` call that guard at startup/request/dispatch boundaries. This proves fail-closed current selection, **not** indexed multi-user serving.
- `mnemo/corpus_identity.py` computes logical path-independent identities. `mnemo_server/services/portable_corpus_runtime.py` inspects source bytes, signed publication, physical database hash and generation evidence for local artifact readiness. Neither automatically publishes an index or grants access.
- `mnemo_server/services/scope_authority.py` persists explicit grants, and `services/authorization.py` checks it when installed. It does not enroll owners automatically and is **not** evidenced as installed for every future indexed CRUD/transport path. This is a visible future security gate, not an inconsistency to paper over.
- `mnemo_server/tools/two_corpus_rebuild.py`, `rebuild_integrity.py`, `source_manifest.py`, and the governed isolated runtime implement build/identity/coverage safeguards for disposable evaluation work. They do not promote a production index. The two manifests reverified against original bytes at 44/44 and 24/24; these counts alone do not certify retrieval.
- The five allowlisted receipts are `COMPLETE`: historical Full V2, shared evaluation, registry Phase 8.5, registry Phase 8.6, and one owned partial rebuild. Their recorded row deltas are 59,937 + 35,067 + 27,791 + 29,285 + 29,322 = **181,402**, including cascades/FTS and not 181,402 unique documents. Current base-file hashes match each receipt's after hash. Original bytes/manifests and recovery snapshots were retained. The empty evaluation registry was inspected; no broad scratch cleanup is claimed.
- The revoked generation is still `REVOKED` with no active generation in the non-secret credential-registry view; a process scan found zero matching certified-tunnel processes. This is a point-in-time local observation, not external transport certification.
- The former `scratch/.venv-gpu-preflight` was manually removed. Its pre-deletion inventory recorded 3,428,879,387 bytes. `scratch/audit_relevance_mapping.py` now selects `.venv/Scripts/python.exe` and fails if missing. Historic GPU A/B equivalence remains untested. The prior bare `pytest` failure is explained by the global executable resolving outside `.venv`; use `.venv/Scripts/python.exe -m pytest` to load its installed `pytest-cov` and apply `pytest.ini` unchanged.
