## Requirement → code → executed evidence

| Requirement | Implementation | Evidence |
|---|---|---|
| Older/newer schema reader errors keep safe origin | `ChunkReadModel` owns an exact schema-reason set and `CHUNK_READ_FAILURE`; `SQLiteStore` translates SQLite failures at chunk, exact-list, advanced canonical and FTS5 read boundaries | Disposable older/newer public MCP matrix; eight direct reader SQL-failure cases; existing schema/FTS5 tests |
| Nested sparse errors and public correlation | Existing fusion wrapper preserves typed `MnemoInterfaceError`; shared `typed_errors.py` now recognizes the exact reader reasons, including nested `UnsupportedError` | Three nested sparse classifier cases; public MCP sparse and exact-chunk errors have category, `contract.storage`, storage layer, reason and UUID; HTTP exact chunk carries the same shape and correlation header |
| Safe partial-result reporting | `advanced.py` reports only allowlisted reader reasons and a static fallback, retaining `FAILED` representation status and partial/unknown completeness | Public old-schema page filter reports unavailable page range; injected advanced snapshot SQL failure reports `CHUNK_READ_FAILURE`, `unknown` completeness, no items, no private SQL in response or log |
| Nondisclosure and scope | Existing authorization-first dispatch is unchanged; raw SQLite exception is chained internally but not reflected publicly; unallowlisted messages remain generic | Existing public unknown/mismatched resource matrix, malicious SQL/path/token injection, unknown-code and nested-error tests; full authorization suite |

Before this change, raw SQLite errors in FTS5 candidate selection, exact chunk hydration and advanced canonical reads could become generic `server_failure` or class-name-only representation omissions. `StorageError("CHUNK_READ_SCHEMA_UNAVAILABLE")` and `UnsupportedError("PAGE_RANGE_UNAVAILABLE_FOR_CHUNK_SCHEMA")` were not classified as reader-owned schema reasons. Now SQL failures become `StorageError("CHUNK_READ_FAILURE")`, and only exact trusted reader reasons survive to the public model. The per-request UUID remains generated by the existing MCP/HTTP request lifecycle; this task does not create another error envelope or correlation scheme.

Advanced canonical retrieval continues to report a failed representation as a partial or unknown result, according to the established contract; it does not convert a failed source into successful evidence. Unsupported page filters on the old physical schema remain explicit omissions, never unfiltered results. No V2-to-V1 fallback, ranking, candidate pool, locator, metadata or authorization logic changed.
