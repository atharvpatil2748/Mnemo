## 1. Explicit Audit Questions & Findings

### Q1: What is already proven by Module 8.1?
- **Handshake & Transport:** MCP server lifecycle over stdio transport and SSE transport with Starlette.
- **Protocol Framing:** Strict stderr logging and stdout isolation ensuring zero corruption of JSON-RPC protocol messages.
- **CLI Executable:** `mnemo-mcp stdio` and `mnemo-mcp sse` entrypoints with configurable host, port, auth mode, and log level.
- **Antigravity Handshake:** Initial stdio connection from Antigravity via `~/.gemini/config/mcp_config.json`.

### Q2: What is already proven by Module 8.2?
- **Tool Definitions:** Registration of all 6 knowledge retrieval tools with strict JSON schemas.
- **Handler Implementation:** Execution logic for `query_notebook`, `search_all_notebooks`, `list_notebooks`, `get_notebook_summary`, `get_source_insights`, and `get_timeline`.
- **Parameter Validation & Error Handling:** Deterministic conversion of validation and not-found errors into MCP protocol error responses (`isError: True`) without stack trace leaks.
- **Unit & Mock Integration Tests:** 34 tests covering mock storage responses and schema conformance.

### Q3: What remains to be proven by Module 8.3?
1. **Real Golden Corpus Data Integrity:** Verification of the live Bhagavad Gita dataset (`data/manual-gita-qa/mnemo.db`, 1,000 indexed chunks, SHA-256: `ff112b0b...`).
2. **End-to-End Golden Corpus MCP Queries:** Invoking all 6 MCP tools against the real indexed dataset and asserting grounded, factual evidence retrieval.
3. **Citation & Synthesis Accuracy:** Verifying that answers generated by `query_notebook` correctly cite exact quotes, heading paths, and page numbers from the Golden Corpus, and that unanswerable/out-of-domain questions do NOT produce hallucinated citations.
4. **Security & Boundary Enforcement:** Proving that no mutation, code execution, filesystem, or shell tools are exposed or callable.
5. **Real Antigravity Client Integration:** Verifying full tool discovery and invocation via the active `mcp_config.json` integration path.
6. **Zero Regression on Project Quality Gates:** Exceeding all gates (Ruff clean, Mypy `--strict` clean, pytest $\ge 90\%$, `uv build --all` clean, 0 frozen-core diffs).

### Q4: What parts of the repository are frozen?
- `mnemo-core/` (Frozen Layer 1).
- `plugins/` (Frozen plugins).
- `docs/adr/ADR-0001` through `ADR-0051` (Historical ADRs).

### Q5: Does an ADR need to be created?
- **No.** The existing architecture and roadmap already specify the testing and integration requirements for Module 8.3.

## 2. Test Plan & Execution Strategy

1. **Step 1: Golden Corpus Verification Test Suite**
   - Author `mnemo-server/tests/test_mcp_golden_corpus.py` executing comprehensive integration tests against the real Golden Corpus database.
   - Test scenarios:
     - Notebook inventory discovery (`list_notebooks`)
     - Notebook summary extraction (`get_notebook_summary`)
     - Source metadata and insight queries (`get_source_insights`)
     - Activity timeline reconstruction (`get_timeline`)
     - Ranked keyword/semantic search (`search_all_notebooks`) for known conceptual terms (e.g., `"Karma-yoga"`, `"duty"`, `"Arjuna"`)

     - Boundary testing: negative queries, non-existent UUIDs, out-of-domain questions (verifying no hallucinated citations)
     - Security testing: rejecting non-existent mutation tools
